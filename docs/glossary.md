# Glossary

Terms as used in Tickbook. Tickbook is a **simulated** venue: wherever a term below mentions money,
orders or trades, it refers to paper balances and simulated activity, never real assets.

| Term                            | Meaning in Tickbook                                                                                                                                                                                        |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account                         | A paper-trading account owned by a firm, holding cash (minor units) and positions. Orders are always placed for an account.                                                                                |
| Aggressor                       | The incoming order that caused a trade by crossing the spread; also called the taker. The trades tape records the aggressor side.                                                                          |
| All-or-none (AON)               | A resting order that may only execute for its full quantity (planned, TB-206).                                                                                                                             |
| Amend (cancel/replace)          | Modifying a resting order. Quantity decreases keep time priority; price changes and quantity increases lose it (planned, TB-210).                                                                          |
| Ask / offer                     | A sell order resting in the book. The best ask is the lowest sell price.                                                                                                                                   |
| Auction (call auction)          | A period in which orders are collected without matching and then executed together at one uncrossing price (planned, TB-520 to TB-524).                                                                    |
| Bid                             | A buy order resting in the book. The best bid is the highest buy price.                                                                                                                                    |
| Buying power                    | Cash available for new buy orders: cash minus cash reserved by the account's resting buy orders across all instruments.                                                                                    |
| Circuit breaker                 | A rule that pauses continuous trading when prices move too far too fast, usually followed by a volatility auction (planned, TB-512).                                                                       |
| CLOB (central limit order book) | The per-instrument book of resting limit orders, organised into price levels on the bid and ask sides.                                                                                                     |
| Command                         | An input to the engine: `place` or `cancel` today; halts, expiries and auctions later. Commands are journaled with a sequence number.                                                                      |
| Crossed book                    | A book whose best bid is at or above its best ask. The engine guarantees this never persists after a command.                                                                                              |
| Depth (L2)                      | Aggregated quantity and order count per price level, without order identities.                                                                                                                             |
| Depth update (diff)             | An incremental change to one price level; quantity 0 removes the level. Applying diffs to a snapshot reproduces the next snapshot exactly.                                                                 |
| Deterministic engine            | The engine is a pure function `applyCommand(state, command) -> (state, events)`. The same journal always produces the same books and trade ids.                                                            |
| Execution report                | What the order owner learns about a fill: trade id, price, quantity and liquidity flag; never the counterparty.                                                                                            |
| Fat-finger check                | A pre-trade risk rule rejecting limit prices too far from the reference (last trade, else the instrument reference price), expressed in basis points (`price_band_exceeded`).                              |
| Fill / trade                    | An execution between a taker and a maker at the maker's price. Each trade has a dense per-instrument trade id.                                                                                             |
| Firm (organization)             | A tenant: the participant that owns users, accounts and orders. Firms trade against each other on the shared books but cannot see each other's private data.                                               |
| FOK (fill or kill)              | Time in force: execute the whole quantity immediately or cancel the whole order with no fills (`fok_unfillable`).                                                                                          |
| GTC (good till cancelled)       | Time in force: any unfilled remainder rests in the book until filled or cancelled. Not allowed for market orders.                                                                                          |
| GTD / DAY                       | Time in force that expires at a given time or at session end (planned, TB-204).                                                                                                                            |
| Halt                            | Operator action suspending order entry for an instrument (planned, TB-510).                                                                                                                                |
| Iceberg order                   | An order that shows only a display quantity; the hidden reserve replenishes the display, losing time priority each time (planned, TB-202).                                                                 |
| IOC (immediate or cancel)       | Time in force: execute what is possible now and cancel the remainder (`ioc_remainder`).                                                                                                                    |
| Journal                         | The append-only, per-instrument table of engine commands with dense sequence numbers. It is the source of truth for book state; recovery replays it.                                                       |
| L1 / L2 / L3                    | Market-data levels: L1 = best bid/ask and last trade; L2 = aggregated depth per price level; L3 = individual orders (planned for surveillance).                                                            |
| Ledger                          | The planned double-entry record of every cash, position and fee movement; balances become projections of it (TB-301).                                                                                      |
| Limit order                     | An order with a price: buys execute at or below it, sells at or above it.                                                                                                                                  |
| Liquidity provider              | A participant (in Tickbook: the seeded market-maker firm, later simulated quoting bots) that keeps resting orders on both sides.                                                                           |
| Lot size                        | The quantity increment for an instrument. Order quantities must be multiples of it (`quantity_not_lot_multiple`).                                                                                          |
| Maker                           | The resting order in a trade; it provided liquidity. Trades execute at the maker's price.                                                                                                                  |
| Market order                    | An order without a price that executes against the best available prices; any remainder is cancelled (`market_no_liquidity`).                                                                              |
| Minor units                     | Integer representation of money: 100.25 USD is stored as 10025. Tickbook never uses floating point for prices or cash.                                                                                     |
| Notional                        | Price multiplied by quantity, in minor units. Limited per order by `max_order_notional`.                                                                                                                   |
| Post-only                       | An order that must add liquidity; it is rejected (or repriced) if it would trade on arrival (planned, TB-203).                                                                                             |
| Price level                     | All resting orders at one price on one side, kept in FIFO (time) order.                                                                                                                                    |
| Price-time priority             | The matching rule: better prices execute first; within a price, earlier orders (lower sequence) execute first.                                                                                             |
| Reconciliation                  | Comparing recovered books with the persisted open orders at boot; mismatches are reported (blocking trading is planned, TB-603).                                                                           |
| Reference price                 | The price used for fat-finger checks and bands: the last trade price, falling back to the instrument's configured reference price.                                                                         |
| Replay                          | Rebuilding engine state by folding journaled commands through the pure engine.                                                                                                                             |
| Risk violation                  | A pre-trade rule failure: `insufficient_buying_power`, `insufficient_position`, `position_limit_exceeded`, `notional_above_max`, `price_band_exceeded`. Risk-rejected orders are stored but not journaled. |
| Sequence number (seq)           | Dense per-instrument counter assigned to each journaled command; also tags market-data messages so clients can order them.                                                                                 |
| Settlement                      | Applying a trade's cash and position movements to both accounts. Today gross and immediate, in the same transaction as the journal entry; fees and ledger postings are planned.                            |
| Simulated venue                 | Tickbook's nature: a teaching and strategy-testing exchange with no real money, no real orders and no external market data.                                                                                |
| Snapshot (engine)               | A planned serialized engine state at a sequence, so recovery replays only the journal tail (TB-602).                                                                                                       |
| Snapshot (market data)          | The full L2 depth sent when a WebSocket client connects or requests `snapshot`.                                                                                                                            |
| Spread                          | Best ask minus best bid. Mid is their average.                                                                                                                                                             |
| Stop / stop-limit order         | An order that becomes active (as market or limit) when a trade prints at or through its stop price (planned, TB-201).                                                                                      |
| STP (self-trade prevention)     | Rules preventing a firm's orders from trading with each other: cancel newest, cancel oldest, cancel both or decrement (planned, TB-205).                                                                   |
| Taker                           | The incoming order that removes liquidity from the book; see aggressor.                                                                                                                                    |
| Tick size                       | The minimum price increment for an instrument. Limit prices must be multiples of it (`price_not_tick_multiple`).                                                                                           |
| Time in force (TIF)             | How long an order stays active: GTC, IOC, FOK today; DAY and GTD planned.                                                                                                                                  |
| Trades tape                     | The chronological list of executions for an instrument, newest first in the API.                                                                                                                           |
| Uncrossing                      | Computing the single auction price that maximises executed volume, then minimises imbalance, then follows market pressure, then stays closest to the reference price (planned, TB-522).                    |
| Venue                           | The simulated exchange as a whole: all instruments, their engines and journals. In the code, `Venue` is the stateful shell that serializes commands per instrument.                                        |
| Venue operator                  | A planned role, separate from firm roles, that administers instruments, sessions, halts and auctions (TB-504).                                                                                             |
| Wash trade                      | A trade where buyer and seller have the same beneficial owner; a surveillance detector is planned (TB-703).                                                                                                |
